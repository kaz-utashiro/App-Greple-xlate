# 匿名化マスク 設計書

日付: 2026-07-06
ステータス: 承認済み(実装前)
前提: ①(llm バックエンド)、②(文脈つき差分翻訳)実装済み

## 背景と目的

xlate の刷新要望 3 点(llm 化・文脈つき差分翻訳・機密情報の匿名化)の
最後。個別名称・案件名などの取り扱い注意情報を、**翻訳 API へ送る段階では
仮名(プレースホルダ)に置換し、訳文で復元**できるようにする。

①の調査で特定した現行 Mask 機構の限界:

- (a) 同一文字列でも出現ごとに別 ID になり、LLM が同一実体と認識できない
- (b) カテゴリ情報(人名・社名等)を持てない
- (c) ②で導入した文脈節(原文スライス・対訳ペア・旧対訳)には
  マスクが適用されず、平文が API に出る
- (d) 原文にタグと同形の文字列があると誤復元し得る(現行からの潜在穴)

## 決定事項(ブレインストーミング承認済み)

- **秘匿範囲は API 送信のみ**: 外部(翻訳 API・llm ログ)には仮名しか
  出さない。ローカルのキャッシュ JSON には従来どおり復元後の平文を保存する
  (キャッシュは手元の管理下という前提。キャッシュ匿名化は非スコープ)
- **プレースホルダはカテゴリ付き XML タグ**: `<person id=1 />`
  `<company id=2 />`。機械的復元が確実で、既存のタグ保護プロンプト・
  復元検証がそのまま効き、カテゴリが LLM の文脈理解にも寄与する
- **実装は Mask.pm の一般化(案 A)**: マークアップ保護(現行 maskfile)と
  匿名化を同じ機構の 2 インスタンスとして扱う。独立モジュールは作らない
- **同一実行内の安定採番**: 同じ文字列は文書中どこでも同じタグ
  (カテゴリ+原文をキーにした対応表)。実行間の永続化はしない
  (タグは訳文に残らないため成果物に影響しない)
- **衝突は自動退避**: 原文にタグ同形の文字列があっても die せず、
  退避層が最初にそれ自体をタグへ置換して保護する(下記)
- **②の文脈節にも適用**: 本文と同じ対応表で匿名化・マークアップ保護を
  文脈にも適用し、秘匿の穴を塞ぐ

## スコープ

- lib/App/Greple/xlate/Mask.pm — 一般化(ルール列・安定採番・参照モード・
  退避層)
- lib/App/Greple/xlate.pm — `--xlate-anonymize=FILE` オプション、
  cache_update での適用順の再編(退避 → 匿名化 → maskfile、文脈への適用)
- lib/App/Greple/xlate/llm/gpt5.pm — プロンプトのタグ例にカテゴリ形を追記

- キャッシュ JSON の匿名化(平文のまま。決定済み)

## 設計

### 匿名化辞書(--xlate-anonymize=FILE)

**辞書は将来ローカル LLM や NER ツールが自動生成する成果物になり得る**
(2026-07-06 ユーザー方針)。生成側の実装は xlate の外(設計哲学どおり)
だが、受け口の形式は機械生成に適した構造化形式を正準とする。

**正準形式: JSON**(ファイル先頭の非空白文字が `[` のとき)

```json
[
  { "category": "person",  "text": "山田太郎" },
  { "category": "person",  "regex": "(?:Mr|Ms)\\. Yamada" },
  { "category": "company", "text": "アクメ株式会社" }
]
```

- オブジェクトの配列。各要素は `category` と、`text`(リテラル、
  quotemeta して使用)または `regex`(正規表現)のどちらか一方を持つ。
  両方あれば die、どちらも無ければ die
- **未知のフィールドは無視する**(前方互換: 生成側が `confidence` や
  `note` 等を付加してもよい。キャッシュ list 形式の第 3 要素と同じ原則)
- LLM に生成させる際の JSON スキーマ例を POD に併記する

**手書き用: 行形式**(JSON でないとき)

```
# コメント行と空行は無視
person   山田太郎
person   /(?:Mr|Ms)\. Yamada/
company  アクメ株式会社
```

1 行 = カテゴリ名 + 空白 + パターン(`/.../` 囲みなら正規表現、
それ以外はリテラル)。バックスラッシュ行継続・`#` コメントは
maskfile と同じ規則。

**共通規則**

- カテゴリ名 = タグ名。`[a-z][a-z0-9_]*` に制限(不正なら die)。
  `lit` は退避層の予約語
- builtin オプション: `xlate-anonymize=s $anonymize_file`
  (%opt キー `anonymize`)
- 想定パイプライン例(ドキュメントに記載。実装はしない):

```sh
llm -m <local-model> -s '機密実体を JSON 配列で抽出せよ(スキーマ...)' \
    < report.md > report.anon.json
greple -Mxlate --xlate-anonymize report.anon.json --xlate ... report.md
```

### Mask.pm の一般化

現行インターフェース(TAG/INDEX/PATTERN、出現ごと採番、mask/unmask/reset)は
**後方互換のまま**残し、以下を追加する。

1. **ルール列**: `RULES => [ [tag => pattern], ... ]`。mask() は各ルールを
   順に適用し、タグ名はルールごと。現行の PATTERN + TAG は
   「単一タグのルール列」として内部的に同じ経路を通す
2. **安定採番**: `STABLE => 1` のとき「タグ名 + マッチ文字列」をキーに
   採番を記憶し、同じ文字列には常に同じタグを返す(カテゴリごとに
   1 起点の独立カウンタ)。既定(STABLE=0)は現行どおり出現ごと採番
3. **参照モード**: `mask_reference(@texts)` — mask() と同じ置換
   (同じ対応表・同じ採番)を行うが、**復元必須集合に登録しない**。
   ②の文脈節のように「送るが応答には返らない」テキスト用。
   unmask() の欠落検証は通常 mask() で置換されたタグのみを対象とする
4. **退避層(タグ同形リテラルの保護)**: `escape_literals(@texts)` —
   タグ同形の汎用パターン `<[a-z][a-z0-9_]* [a-z0-9_]+=\d+ */>` に
   一致する既存文字列を `<lit id=N />` へ置換する(安定採番)。
   **最初に**全テキスト(本文+文脈)へ適用し、復元は**最後**に行う。
   これにより処理中のテキストに存在するタグはすべて自前生成となり、
   復元の完全一致置換が誤爆しない。maskfile の原文に退避タグが含まれる
   入れ子ケースも、復元順序(maskfile → 匿名化 → 退避)で正しく巻き戻る。
   タグ名 `lit` は辞書のカテゴリ名として予約(使用したら die)

### 適用順序(cache_update)

```
mask:   ①退避層  — 本文: 追跡 / 文脈: 参照モード
        ②匿名化  — 本文: 追跡 / 文脈: 参照モード
        ③maskfile — 本文: 追跡 / 文脈: 参照モード
unmask: ③maskfile → ②匿名化 → ①退避層 の逆順。
        欠落検証は本文由来(追跡)のタグのみ(現行同様 die)
```

(退避層も本文に置いたタグは応答に返る必要があるため追跡し、
文脈に置いたものは参照モード — 3 層とも同じ区別に従う)

- 文脈($call_context)への適用は**複製に対して**行う
  (postgrep が組んだ構造や %cache の値を書き換えない)。
  対象: source_before / source_after / hits_before・hits_after・old_pairs の
  各ペアの原文と訳文
- 匿名化辞書・maskfile のどちらか(または両方)が未指定なら、
  その層は単にスキップ。どちらも無ければ退避層も走らせない
  (完全に現行動作のまま)
- dryrun および --xlate-mask プレビューは匿名化適用後の姿を表示する

### プロンプト

gpt5 のタグ保護指示のタグ例を 1 箇所だけ拡張する:

```
(e.g., "<m id=1 />" or "<person id=2 />")
```

(既存文言は「XML-style marker tag」と一般形なので、これ以外の変更は不要。
このプロンプト変更は①のキャッシュ同等性前提をさらに離れるが、②で
同種の変更を許容済み — キャッシュキーは原文なので既存ヒットに影響しない)

### エラー処理

- 辞書のパースエラー(不正カテゴリ名、`lit` の使用、壊れた正規表現)は
  読み込み時に die
- 応答からの本文由来タグ欠落は現行同様 die(②の失敗時保護 —
  checkpoint + 凍結 — がそのまま効くため、失敗してもキャッシュは無傷)
- 幻覚で応答に対応表にないタグ形文字列が現れた場合は文字として残る
  (現行と同じ)

## テスト計画(すべてスタブ llm、API 費用ゼロ)

1. **Mask.pm 単体(t/13_mask.t 新規)**
   - 後方互換: 現行の PATTERN/TAG 経路の挙動が不変(出現ごと採番)
   - 安定採番: 同一文字列 2 出現が同一タグ、カテゴリ独立カウンタ
   - 参照モード: 置換はされるが unmask の欠落検証対象にならない
   - 退避層: タグ同形リテラルの置換と、入れ子(maskfile 原文内の
     退避タグ)を含む逆順復元の往復一致
   - 辞書パース: JSON 形式(text/regex、未知フィールド無視、text と
     regex の同時指定 die、不正 JSON die)/行形式(リテラル/正規表現/
     継続行)/不正カテゴリ die/lit 予約 die/形式自動判別
2. **パイプライン(t/11 追記)**
   - 辞書指定で実行: スタブへの stdin(本文)と -s(文脈節)の両方から
     機密文字列が消えタグに置換されていること、出力では復元されていること
   - 同一人物が本文と文脈で同じタグになっていること
   - maskfile と併用したときの適用順と復元
   - 原文に `<person id=1 />` リテラルを含む文書で、退避層が働き
     出力で原文どおり復元されること
   - 匿名化未指定の実行が完全に従来どおりであること(回帰)
3. 実 API 確認は手動レシピ(承認後、数円): 辞書つきで 1 段落翻訳し、
   `--xlate-debug` で送信内容に平文が無いことを確認

## 互換性

- maskfile の現行動作(出現ごと採番・本文の追跡復元)は不変。
  ただし③以降の変更が 2 点ある: (1) maskfile も文脈へ参照モードで
  適用される(品質向上のみ)、(2) maskfile 単独指定でも退避層が有効に
  なり、原文のタグ同形文字列による誤復元の穴(背景 (d))が塞がれる
  (挙動変更だが安全側の修正)
- キャッシュ形式・キーは不変(平文)。匿名化の有無はキャッシュ互換に
  影響しない
- 匿名化を指定しない実行は退避層も含めて走らず、完全に現行動作
