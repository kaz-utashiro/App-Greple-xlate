# xlate CLI 2.0 刷新 設計書

2026-07-07。モジュール 2.00(llm バックエンド、文脈差分翻訳、匿名化、
テンプレート)に合わせて `script/xlate` と `share/XLATE.mk` を刷新する。
メジャーバージョンアップとして非互換変更を許容する。

## 方針

最小差分改修。bash + getoptlong.sh の現行構造(宣言的 OPTS 表 →
greple コマンド組み立て → exec)を維持し、サブコマンド化はしない。
Docker(dozo)統合・ファイルタイプ別パターン選択は変更しない。

## 1. 既定値の変更(非互換)

### 1.1 既定エンジン: deepl → gpt5

`script/xlate` の `: ${engine:=deepl}` を `: ${engine:=gpt5}` に変更。

- `-e deepl` で従来動作。
- 注意: キャッシュファイル名はエンジン名を含む
  (`FILE.xlate-deepl-JA.json` / `FILE.xlate-gpt5-JA.json`)ため、
  deepl 利用者が無指定で実行すると gpt5 の新キャッシュが作られる。
  POD の非互換一覧に明記する。

### 1.2 API 呼び出しを既定に(--no-api で labor)

現行は `-a/--api` を付けない限りクリップボード手動翻訳(labor)が
既定(`[[ ${api:-} ]] || use_clipboard=yes`)。これを反転する。

- OPTS 表で api フラグの初期値を 1 にする(`[ api | a # ... ]=1`)。
  getoptlong.sh の `no-` 否定により `--no-api` で偽になる
  (実挙動確認済み: 既定 `api=1`、`--no-api` で空、`-a` は真のまま)。
- 無指定・`-a`: `--xlate`(API 翻訳)。`-a` は「明示的に既定を指定」
  する有効なオプションのままで、警告も廃止予定表示もしない。
- `--no-api`: `--xlate-labor`(クリップボード手動翻訳)。
- `use_clipboard` 変数は廃止し、`[[ ${api:-} ]]` 直接参照にする。
- 専用の `--labor` オプションは設けない。

### 1.3 -c/--check との関係

現行の「`--check` 時は `--xlate` を付けない」動作は維持する
(翻訳対象領域のハイライト確認)。

## 2. 新オプション

すべて long 名のみ(短文字は追加しない)。getoptlong OPTS 表への追加
エントリと greple オプションへのマッピング:

| CLI オプション | OPTS 型 | 展開先 |
|---|---|---|
| `--anonymize=FILE` | `:` | `--xlate-anonymize=FILE` |
| `--mark[=REGEX]` | `?` | `--xlate-anonymize-mark=REGEX`(値省略時 `--xlate-anonymize-mark=`) |
| `--template[=REGEX]` | `?` | `--xlate-template=REGEX`(値省略時 `--xlate-template=`) |
| `--frontmatter` | flag | `--xlate-frontmatter` |
| `--seed=FILE` | `:` | `--xlate-cache-seed=FILE` |
| `--context=N` | `:` | `--xlate-context-window=N` |

- getoptlong.sh は `?`(optional value、`_IS_MAYB`)をサポートすることを
  確認済み。
- CLI は常に `--xlate-template=` のように `=` 連結で組み立てるため、
  モジュール側の「値省略オプションが後続ファイル名を吸う」罠は CLI
  経由では発生しない。

### 2.1 -n の段階化(送信内容プレビュー)

`dryrun` フラグを `+`(カウント型)に変更する(実挙動確認済み:
`-n`→1、`-nn`→2)。

- `-n`(1 回): 従来どおり、実行せず greple コマンド列を echo
- `-nn`(2 回以上): greple を **実行**するが `--xlate-dryrun` を
  付ける — 翻訳 API は呼ばず、送信ペイロード(匿名化・マスク適用後)
  を進捗表示に出す
- make モード(`-M`)では回数によらず従来どおり `make -n`

専用の `--preview` オプションは設けない。

## 3. ファイルタイプ別既定パターン

現状維持(`*.txt` / `*.md` / `*.pm` / `*.pod` / msdoc 系 / その他)。
`*.md` でも `--frontmatter` / `--template` は自動付与しない(明示指定
のみ。意図しない除外・検証事故を防ぐ)。

## 4. share/XLATE.mk

### 4.1 既定エンジン

`XLATE_ENGINE ?= deepl` → `XLATE_ENGINE ?= gpt5`

### 4.2 新 make 変数

greple オプションに展開する変数を追加(値が空なら何も加えない):

| 変数 | 展開 |
|---|---|
| `XLATE_ANONYMIZE` | `--xlate-anonymize=$(XLATE_ANONYMIZE)` |
| `XLATE_MARK` | `--xlate-anonymize-mark=$(XLATE_MARK)`(値 `1` のとき空値 `=` で既定記法) |
| `XLATE_TEMPLATE` | `--xlate-template=$(XLATE_TEMPLATE)`(値 `1` のとき空値 `=` で既定記法) |
| `XLATE_FRONTMATTER` | 非空なら `--xlate-frontmatter` |
| `XLATE_SEED` | `--xlate-cache-seed=$(XLATE_SEED)` |
| `XLATE_CONTEXT_WINDOW` | `--xlate-context-window=$(XLATE_CONTEXT_WINDOW)` |

`xlate -M` からの引き渡し: script/xlate の make 分岐に、CLI で指定
された新オプションを対応する XLATE_* 変数として渡す行を追加する
(既存の `XLATE_MAXLEN=${maxlen:-}` と同じ流儀)。

### 4.3 新制御ファイル: FILE.ANONYMIZE

`FILE.ENGINE` と同じ「対象ファイルの横に置く」流儀。
`FILE.ANONYMIZE` が存在すれば、それ自体を匿名化辞書として
`--xlate-anonymize=FILE.ANONYMIZE` を付ける(パスを書くのではなく
ファイルそのものが辞書。JSON / 行形式はモジュール側が自動判別)。
`XLATE_ANONYMIZE` 変数より優先する。

## 5. ドキュメント(script/xlate 内 POD)

- SYNOPSIS / ヘルプ表: 新オプション 6 個を追加、`-a` の説明を
  `use API (default; negate with --no-api)` に、`-n` の説明を
  `dry-run (-nn: preview transmission)` に変更
- エンジン一覧: `(*gpt5, deepl, ...)` に更新(`*` = 既定)
- OPTIONS 節: 各新オプションの説明(モジュール側 POD の要約+参照)
- 新節「INCOMPATIBLE CHANGES IN 2.x」: §1 の 3 点(既定エンジン、
  API 既定化、-a no-op)とキャッシュファイル名の注意
- EXAMPLES: テンプレート運用の実例 1 本(--frontmatter --template
  --anonymize と pandoc-embedz の連携。モジュール POD の
  ANONYMIZATION AND TEMPLATES と同じ題材)
- Control Files 節: `*.ANONYMIZE` を追加
- `lib/App/xlate.pm` はリリースフックが script/xlate の POD から
  自動再生成するので直接編集しない

## 6. テスト(新規 t/16_cli.t)

`xlate -n`(echo モード)は greple を実行せずコマンド列を出力する
ため、API もモジュールも不要の純粋なコマンド組み立てテストができる。
bash と getoptlong.sh(Getopt::Long::Bash 依存で導入済み)があれば
CI でも動く。

検証項目:

1. 既定: `xlate -n -t JA f.txt` → `--xlate-engine=gpt5` と `--xlate`
   (labor でない)を含む
2. `--no-api` → `--xlate-labor`
3. `-a` → echo 列が既定と同一(明示的既定として有効)
4. 新オプション 6 種のマッピング(--anonymize/--mark/--mark=R/
   --template/--frontmatter/--seed/--context)
5. ファイルタイプ: `f.md` と `f.pm` で area パターンが変わる
6. `-e deepl` で `--xlate-engine=deepl`
7. `-nn`: greple を実行し `--xlate-dryrun` が付く。スタブ llm
   (t/bin を PATH 先頭に)+空キャッシュで実行し、送信ペイロードが
   表示され翻訳出力が原文のままであること(他のモジュールテストと
   同じ実行環境で API 不要)
8. XLATE.mk: `make -n -f share/XLATE.mk XLATE_ANONYMIZE=dict.json ...`
   で greple コマンドに `--xlate-anonymize=dict.json` が現れる。
   `FILE.ANONYMIZE` を置いた場合の自動付与も `make -n` で検証

既存 t/ スイートの流儀(Test::More、t::Util)に従うが、Runner は
greple 用なので直接 bash を叩く小ヘルパーを t/16 内に持つ。

## 7. 非互換一覧(Changes 起草用)

1. 既定エンジンが deepl から gpt5 に変わった(キャッシュファイル名に
   影響。従来動作は `-e deepl`)
2. API 翻訳が既定になった(クリップボード手動翻訳は `--no-api`。
   `-a/--api` は明示的既定として引き続き有効)

- Docker イメージ(llm は 1.0202 で導入済み、変更不要)
- share/xlate.el(xlate コマンドの外部仕様変更は -t 必須等に影響なし)
- サブコマンド化・設定ファイル(~/.xlaterc)の拡張
- モジュール側(lib/)の変更
